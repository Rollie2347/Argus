# CLAUDE.md

Guidance for Claude Code (claude.ai/code) working in this repository.

## Canonical directory

Use `Argus/` (capital A). An older lowercase `argus/` Python/FastAPI prototype may exist on some local machines (referenced by `start.sh`, a leftover hackathon layout) — it is **not** in the GitHub repo and is not current.

## What this is

Real-time multimodal AI life companion on the Gemini Live API (vision + voice), built for the Gemini Live Agent Challenge. One WebSocket connection = one persistent Gemini Live session, with camera frames, mic audio and tool calls flowing bidirectionally.

## Commands

No lint anywhere; mobile has no test suite; no CI beyond the Claude Code workflows in `.github/workflows/`. `backend/` has a minimal smoke suite.

**Backend**
```bash
cd backend
npm install
cp .env.example .env   # set GEMINI_API_KEY, GCP_PROJECT_ID at minimum
npm start              # node server.js — http://localhost:8080
npm run dev            # node --watch server.js
npm test               # node --test "test/**/*.test.js"
cloudflared tunnel --url http://localhost:8080   # HTTPS tunnel, required for phone camera/mic testing
```
Local dev also needs a Firestore `backend/service-account.json` (gitignored); Cloud Run uses default credentials. The local backend env file does not exist on the current dev machine — recreate it if local dev resumes.

`npm test` = `backend/test/server.smoke.test.js` (Node's built-in `node:test`, no new dependency): spawns the server with throwaway creds, checks `GET /api/health` and the WS auth gate (missing / wrong / correct secret, asserting the `4001` close). It deliberately does **not** exercise a real Gemini round trip (needs a real key, costs money per run) — so it cannot catch any Live-API-shaped bug. Run one file with `node --test test/server.smoke.test.js`; use the quoted-glob form for all, since `node --test test/` (directory form) fails to resolve on Windows/Git Bash.

**Deploy**
```bash
./deploy-cloudrun.sh YOUR_GEMINI_API_KEY YOUR_WS_SHARED_SECRET [LAT LON TIMEZONE MAX_GLOBAL_CONCURRENT_SESSIONS]
```
Hardcoded project `agus-488919`. Enables Cloud Run/Artifact Registry/Cloud Build/Firestore and deploys with session affinity (required — WebSockets must stick to one instance). Current shape: `--memory 2Gi --cpu 2 --min-instances 1 --max-instances 20 --concurrency 25 --timeout 3600` (see #36 for why CPU, not memory, is the binding constraint, and why `timeout 3600` matters). `GEMINI_API_KEY` and `WS_SHARED_SECRET` are both required startup vars — the server exits immediately if either is missing. ## Architecture

- **Backend is a stateful relay, not a REST API.** `server.js` upgrades each `/ws` connection, opens one Gemini Live session per connection, and pipes camera JPEGs (`image/jpeg`) and mic audio (`audio/pcm;rate=16000`) to Gemini, streaming audio/text/tool-call responses back. Session lifetime = connection lifetime.
- **Tools are in-process functions.** `backend/agents.js` holds 20 Gemini function declarations, their handlers, and the system prompt (Argus = proactive, warm, concise; 1–3 sentence voice replies): `identify_scene`, `read_text`, `get_recipe_suggestion`, `cooking_timer`, `compare_products`, `diagnose_problem`, `manage_shopping_list`, `remember_preference`, `forget_memory`, `recall_memory`, `get_weather`, `log_daily_activity`, `get_daily_summary`, `web_search`, `read_webpage`, `find_places_nearby`, `research_topic`, `research_place`, `update_profile`, `mark_profile_reviewed`. `server.js` executes the handler and feeds the result back into the same session.
- **Memory is Firestore, keyed by user**, in two tiers (see #40).  `backend/memory.js`: `users/{userId}` profile, `users/{userId}/daily/{date}`, `users/{userId}/lists/shopping`, `users/{userId}/observations/*`.
  - **Global tier — always injected into the system instruction:** `name`, `homeLocation {city, lat, lon, updatedAt}`, `people [{name, relation}]` (max 15), `personality {tone, verbosity, proactivity}`, `dietaryPreferences`, `allergies` (each capped at 25 entries), `lastProfileReviewAt`. Flat top-level fields deliberately, never a nested `profile` map (see #16).
  - **Local tier — read on demand only:** `preferences` map, `daily/`, `lists/shopping`, `observations/`. `buildMemoryContext` clamps its whole output to 600 chars.
- **Auth.** Every WS connection must present `WS_SHARED_SECRET` in its first `{type:"user_id"}` message (`crypto.timingSafeEqual`); missing/wrong closes with `4001` before any geo lookup or Gemini session opens. `frontend/index.html` gets the secret injected server-side per request (`serveIndexWithSecret`); mobile reads `EXPO_PUBLIC_WS_SHARED_SECRET`. **See #12 and #34 — this gate is far weaker than its name implies.**
  - Beyond that gate, tool calls and memory reads trust the self-asserted `userId` alone. Destructive/PII HTTP calls require a separate per-user device secret: `POST /api/user/:userId/claim` mints a one-time 256-bit secret the first time that userId's doc is created (the transaction refuses with `409` if the doc already exists — **do not loosen this, see #24**); `DELETE /api/user/:userId` and `GET/POST /api/user/:userId/profile` require it as `Authorization: Bearer <secret>` (`verifyDeviceSecret`, timing-safe) and 403 otherwise. Mobile stores it in Keychain via `expo-secure-store` under a **per-uid** key (see #24).
  - `server.js` also enforces per-IP HTTP rate limiting on `/api/*` (300/min), a per-IP WS connection cap (`WS_MAX_CONN_PER_IP`, default 50), per-connection message-rate limiting, message type/size validation, and a Firestore-backed fleet-wide `MAX_GLOBAL_CONCURRENT_SESSIONS` (default 400, close code `4029`). The per-IP limits are in-memory per instance; only the global cap coordinates across instances.
  - `sessionsByUser` closes any prior session for a `userId` (code `4002`) before opening a new one.
  - `GET /privacy` serves `frontend/privacy.html`.
- **Geo/weather.** IP geolocation via `ip-api.com` (plaintext HTTP — responses are sanitized before reaching the prompt, see #32), cached per IP. `weather.js` calls Open-Meteo (no key) with a 3s timeout, cached 30 min in a `Map` keyed by rounded lat/lon, and provides `geocodeCity` for `homeLocation`.
- **`frontend/index.html`** is the reference client: JPEG frames every ~2s, PCM16 mic in, PCM24 playback. Fastest way to confirm the pipeline end-to-end.
- **`mobile/`** connects via `services/websocket.ts` (`ArgusSocket`), streams mic audio, captures camera frames adaptively (2s while a turn is in flight, 5s idle — see #37), and plays incoming PCM through a queued `Audio.Sound`, WAV-wrapped (expo-av cannot play raw PCM buffers). Gain lives in `mobile/services/audioGain.ts` — the single definition, imported by both playback and the A/B harness (see #43).

## Working conventions (learned the hard way — read before debugging anything)

**Standard pre-ship verification**, assumed by every "verified" note below unless stated otherwise: backend `node --check <file>` + `npm test`; mobile `npx tsc --noEmit` + `npx expo export:embed --eager --platform ios --dev false` (reproduces EAS's exact "Bundle JavaScript" step locally, so build failures are caught without burning a build). These prove it compiles and bundles — **never** that a fix works.

**Verify what is actually deployed, not what was committed.** Deploys here are routinely done *before* the commit, so comparing timestamps misleads. Pull the live image layer from Artifact Registry via the Docker Registry HTTP API (`curl` with a `gcloud auth print-access-token` bearer token against `us-central1-docker.pkg.dev/v2/.../manifests|blobs/...` — `docker` itself is often not running) and hash it against HEAD. Better still where possible, prove behaviour black-box: a `403` from `/api/user/<id>/profile` with no auth header proves the auth code is live in a way no hash does. `GET /api/health` proves nothing about the Gemini key — it returns static config and passes with a dead key; only `{type:"connected"}` from a real WS session proves that.

**Verify what is actually on the phone.** `npx eas build:list --platform ios --json`, then diff the reported `gitCommitHash` against the commit carrying the fix. **This file's "not yet built" / "shipped in build N" claims have been wrong at least four times**, once costing a whole session of debugging a fix the device never had (see #39's correction). See the `argus-claudemd-status-claims-unreliable` memory note.

**Confirm the live uid before concluding a memory/profile feature is broken.** Read it from `User:` or `POST /api/user/<uid>/claim` lines in the request logs. Reinstalling (vs updating) the app wipes `AsyncStorage`, so `argus_uid` is regenerated; Keychain survives. Checking the wrong Firestore doc has produced a false "broken" report **twice** (#40, #43).

**Mojeek throttles this dev machine's IP, so `web_search` and `research_topic` cannot be exercised locally.** The signature is a **200 with ~5.5KB and zero `<li class="rN">`** instead of ~19.6KB of results; it is IP-based, not User-Agent-based (a full browser UA changes nothing). Production is unaffected — Cloud Run's egress IP is different and the logs show `web_search` succeeding in 87–200ms. **Do not "fix" the parser in response to this**, and do not hammer it hoping the block lifts. Verify the parser against captured markup, and verify everything downstream of the search call with real URLs instead.

**A message the server silently ignores is invisible twice over** — once to the user and once in the logs. `greet` was gated on `&& session` with no else branch for months (#49). When adding a client message type, either handle the not-ready case or log the drop; and remember `ws` **discards messages that arrive with no `message` listener attached** — it does not buffer them, so any `await` between detaching one listener and attaching the next is a hole.

**Logs:** `gcloud logging read "resource.type=cloud_run_revision AND resource.labels.service_name=argus" ...`, usually needing a fresh `gcloud auth login`. Use PowerShell, not Bash. Filter HTTP requests with `httpRequest.requestMethod=DELETE` etc. See the `argus-gcloud-cli-setup` memory note.

**⚠️ `gcloud run services describe` prints `GEMINI_API_KEY` in plaintext** into the transcript (`WS_SHARED_SECRET` comes back redacted; the Gemini key does not). This is what forced the 2026-08-09 key rotation. See action item 5 for two more `gcloud` secret-leak traps.

**Log lines worth grepping** (all emitted by `server.js`):

| Line | Meaning |
|---|---|
| `🎤 Audio chunks: N` | Logged at `N % 100 === 1`. **Its absence proves zero mic chunks arrived** (#33). |
| `🎯 Response latency` | The only trustworthy latency metric (#42). |
| `⏱️ Turn latency: Nms` | Saturated at ~1s — do not use (#35). |
| `🗣️ Response turn started — Nms quiet since last turn ended` | Includes the user's speaking time (#35). |
| `🔇 Turn complete — N audio chunks over Nms` | Turn duration (#35). |
| `🎙️ User speech detected` | From `inputAudioTranscription` (#35). |
| `⚡ Gemini interrupted its own response` | Barge-in. Rate = these ÷ turn-completes (#41–#44). |
| `♻️ Superseding prior session` | `sessionsByUser` closed a duplicate (#33). |
| `🎤⚠️ Mic gap` | Client stopped sending when it shouldn't (suppressed while a response is in flight, #44). |
| `⏱️ Tool <name>: Nms` / `⏱️ reserveGlobalSlot: Nms` / `📝 System instruction built` | Firestore timings (#42, #43). |
| `Location:` | Absent = geo cache hit (#40). |

**Latency: use `🎯 Response latency` (last user speech → response start) and nothing else.** `⏱️ Turn latency` is structurally saturated at ~1s (it measures time since the last 1s mic chunk, which arrives regardless of speech — #35), and `🗣️ ...quiet since last turn ended` includes the user's own speaking time, so it overstates wildly.

**Firestore:** `set(..., {merge:true})` does **not** split dotted keys into nested field paths the way `update()` does — `preferences.foo` becomes a literal field name containing a dot. This caused #16 and left orphaned data that #37 had to recover. Same behaviour applies to `FieldValue.delete()` keys, which must be passed raw, not escaped.

**App Store, two steps that have each bitten twice:**
1. Uploading to TestFlight (`eas submit`) does **not** select a build for review — that is a separate manual step on the app's **App Store** tab (not the TestFlight tab). Leaving it stale caused Apple to review a months-old build once (#23).
2. Bump `app.json` `"version"` whenever Apple has approved the current one. `eas.json`'s `autoIncrement` only bumps the build number (`CFBundleVersion`), never the marketing version; a closed version train rejects with `ITMS-90186`/`ITMS-90062` (#29, #38). Currently `1.0.3`.

**Local Expo modules:** the podspec must live in the module's `ios/` subdirectory, not its root — `expo-modules-autolinking` only searches one level into subdirectories. Verify with `npx expo-modules-autolinking resolve --platform apple --json` before building (#39).

**Editing `mobile/patches/expo-av+16.0.8.patch` by hand is error-prone** — hunk line counts must be recomputed or `patch-package` rejects the file with only a "parse error" link. Always verify with `rm -rf node_modules/expo-av && npm install` plus a `grep` for each expected change before building (#41).

## Do not re-try these (each already cost real time or a crash)

- **`realtimeInputConfig.automaticActivityDetection`** in `ai.live.connect`. Tried twice — raised to 1500ms (#27) and lowered to 500ms (#41) — and produced an identical fatal `1007 The audio content type (CONTENT_TYPE_AUDIO) is not supported for this model configuration` mid-conversation both times. Opposite parameter directions, identical failure ⇒ **the trigger is the field existing on this preview model, not its value.** A permanent DO-NOT-RE-ADD comment sits where the block was.
- **Explicit `contextWindowCompression` `triggerTokens`/`targetTokens`** — same config class as the above; the default (80%) is deliberate (#37).
- **`thinkingConfig.thinkingBudget = 0`** — measured *worse*, not better: ≈1986ms vs ≈1733ms default, plus one full non-response on the disabled arm (#40). The `THINKING_BUDGET` env var remains for future testing; unset = model default.
- **Rewording the prompt to make the model chain tools, without first checking the tool-call histogram in the logs.** Done once; the chaining instruction was already there and already specific, and the real causes were a contradictory prompt line and a tool that dead-ended (#47).
- **A second search provider as a Mojeek fallback.** Probed 2026-08-27: `searx.be` serves HTML with JSON disabled, `searxng.site` 403s, `priv.au` 429s, Marginalia is a niche non-commercial index, Wikipedia's opensearch is encyclopaedic only. None is verifiable or better. Mojeek works fine from Cloud Run — the throttling is **this dev machine's IP**, not the service.
- **DuckDuckGo's `html/` or `lite/` endpoints for `web_search`** — both answer `202` with an anomaly challenge page. Use Mojeek (#46).
- **Buffering suppressed mic chunks and flushing them at turn end** (#44) — the buffer contains Argus's own voice echoed through the mic, so flushing risks Argus answering itself. Needs an energy/echo test first, not a naive flush.
- **`CHUNK_MS` below 1000** in `home.tsx` — 400ms was measurably worse (more cutout, felt slower), because `Audio.Recording`'s fixed native prepare/start/stop overhead is a much larger fraction of a short window (#38).
- **A native `AVAudioEngine` rewrite** — attempted over 6 build cycles (32–37) and abandoned with no audible output ever achieved, on a Windows dev machine with no Mac/Xcode debugger (#39).
- **Loosening `claimUserSecret`'s "refuse if the doc exists" guard** — flagged in security review as account takeover, since userIds appear in plaintext in Cloud Run logs (#24).
- **Half-duplex (muting the mic while Argus speaks) as a fix for muffled audio** — the sample-rate clamp it assumed was measured and ruled out (#42). Note this is unrelated to the *send*-gating in #44, which is about interruption and does work.
